# Controls

A control is anything kept to stop a failure: a test, a check, a runtime guard, a
review, a rule in a standard or a step in a procedure. Each control below names the
[risks](risks.md) it serves, how it reduces them, what it costs, what it does not
cover and where it is enforced. A control that cannot name a risk in the register and
a realistic way it reduces that risk is not added, and one that loses its risk is
removed ([control rule](standards/authority.md#control-review)).

Automatic controls run in `tools/check.py`; the [CI profiles](workflows/ci-profiles.md)
say which profile runs what. Runtime controls act in the running system, and their
tests are part of C-PORTABLE. Manual controls are a named review or procedure step.
The [testing guide](testing.md) maps test files to the responsibilities they protect.
