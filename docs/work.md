## Campaign delivery path

[Outcome #10](https://github.com/CVX-Hull/enactive/issues/10) requires a normally
created fresh character alive after seven elapsed game days, maintained needs,
useful supplies/shelter/rest, meaningful travel/threat decisions, normal
save/restart, actual player handoff, a watchable graphical UI and user Pause.
Routine play and recovery must not need user keys or lead tactical rescue.

## Selected independent-player iteration

Use the delivery brief and [#145](https://github.com/CVX-Hull/enactive/issues/145)
for the selected full outcome; use the public Project for sequencing/allocation.
Component readiness permits shared native validation without a separate ceremony
at every skill boundary. A short mission, passing tests or an investigated
failure cannot substitute for the full independent campaign.

The first campaign motivates composition and memory: its water corrections require
separating produced, stored, carried, consumed and historical stock; interrupted
craft and uncertain rest require separating delivery from observed effects.
Retrieve memory at meaningful planning, changed-state, correction and handoff
boundaries. Facts, procedures and advisory output never grant input authority.
Functional reuse does not establish causal learning benefit or justify a critic
per key. The [memory](design/procedure-learning.md),
[mixed-input](design/mixed-input.md), [organic-discovery](design/organic-discovery.md)
and [reflection](design/asynchronous-reflection.md) designs own those boundaries.

P-CHANGE/S-CODE allow deliberate accelerators over the longer project horizon;
immediate payback and precise ROI are not prerequisites. Assess available engine,
platform, library and tool capabilities before adding infrastructure. Checkpoint
reuse [#175](https://github.com/CVX-Hull/enactive/issues/175) is one conditional
investment, with ordinary Save/Load and new provenance. It does not authorize
resuming a failed mission or make another framework a campaign gate.

## Execution ownership

Follow [S-AGENT](engineering.md#s-agent-accountable-agent-assisted-work) and the
[designated-player contract](protocol.md#designated-campaign-operator): the lead
owns engineering, integration, admission and acceptance; one designated player
owns deciding input and routine gameplay reasoning. Read-only advice/review can
run alongside play. Handoff must establish actual quiescence and new bounded
authority; status text alone cannot prove an empty tool queue. The waypoint
planner remains candidate-only. No source/save/build changes occur during a
frozen deciding run.
