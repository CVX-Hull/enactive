## Decisions

Keep the same SDK, exact selected snapshot cache, canonical requests, immutable
ledger, single writer and ordinary input capability. No menu handler, tactical
script, new authority, compatibility reader or per-action approval is introduced.
The model chooses meanings, evidence, intent, code and finite limits; software
continues to bind mechanical metadata. Do not remove automatic next_snapshot and
force another model call merely to obtain current context.

Replace the broad default mission serialization with a maintained decision view:
current ownership/phase, next decision, selected evidence, original remaining
capacity/reserves, Pause, delivery uncertainty, current visible information and
relevant memory/advice state. Keep the complete selected cached mission accessible
through the existing as-of detail tool. No detail read refreshes or retargets it.
Remove mechanical clocks/configuration/history from ordinary defaults where the
exact detail reference preserves access. Retain nonmatching native/source views,
unknown outcomes and every outstanding collection obligation. Opaque memory,
handoff, source and advisory records retain their canonical meaning.

Make the read-only nature of snapshots explicit without suggesting a constant
grants_authority=false is a failure to adopt or execute. A snapshot never grants
authority; the writer checks actual requests. The next-needed-decision and active
phase determine the documented workflow. Do not invent a cached readiness promise.

For malformed discriminated tool intents, use the existing JSON Schema validator
against the selected current branch to report useful field-level errors. This is
diagnostics only: full schema validation remains mandatory before staging; no
defaults, guessed input, retries or repaired submissions. Reuse jsonschema rather
than build another validation language. Keep the message bounded and avoid dumping
the submitted payload or all unrelated branches. Valid SDK requests retain their
current contract and behavior.
