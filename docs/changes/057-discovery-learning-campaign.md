## Ordinary-input foundation and artifact impact

Ordinary keys/text/clicks are the foundation; semantic skills and visible-label
shortcuts are optional accelerators. A player must be able to observe an unfamiliar
or changed interface, attempt an input, inspect the returned evidence and choose
again without waiting for an engineering handler. The [mixed-input design](../design/mixed-input.md)
owns the selected migration and current limits; the [organic-discovery design](../design/organic-discovery.md)
cross-checks earlier memory, monitoring and embodied-agent research.

The coherent foundation separates the immutable model-informing source, actual
native preflight and after-evidence. Ordinary events can admit changed pixels
under current physical-receiver/custody checks without claiming unchanged meaning.
Semantic interpretations retain their stricter source/image promises. Authenticated
input delivery is distinct from semantic success and later processing/storage.
Known ACKs retain their original evidence if processing fails; real storage faults
still stop. The bounded navigation projection may forget routes without deleting
durable evidence or revoking ordinary input solely because its optional cache is
full. Native receiver attestation uses live context provenance and precedence,
not a list of familiar menu names. None of this proves cross-game qualification.

Current behavior and exact versions belong in [architecture](../architecture.md)
and [protocol](../protocol.md), schemas and executable callers/readers. No
compatibility path is retained. The [learning006 report](../acceptance/2026-10-22-discovery-learning-sixth-attempt.md)
records actual graphical discovery and normal lifecycle on its identified
source/native candidate. The [fresh003](../acceptance/2026-10-22-independent-seven-day-third-attempt.md),
[fresh004](../acceptance/2026-10-22-independent-seven-day-fourth-attempt.md) and
[fresh005](../acceptance/2026-10-22-independent-seven-day-fifth-attempt.md) reports
retain later cache, capture and lifecycle failures. A passing source test does
not erase those failures or establish native/independent survival support.

### Save observation versus action

Fresh005's player independently chose to end after a tactical failure; Save then
refused before input. Exported native state matched apart from capture identity
and time, while the actual images differed in 72 minimap pixels. The animation
cause and a successful normal ending are unproved.

The selected correction retains the original private `save_start` root,
first-normal source, deadlines and cumulative costs while exposing the new
checkpoint after a healthy native-state-equal PNG change. The old decision returns
blocked without input or rotation; the player must inspect that image and choose
a NEW same-root Save request. Explicit Observe can update the same checkpoint.
Cancellation, lease, quiescence, original root/mission limits and retained evidence
remain enforced. Mapping capacity cannot exhaust before the input ceiling under
the admission's mappings-at-least-inputs invariant.

Catching an evidence error alone was rejected because ingestion had already
advanced current evidence and left the phase inconsistent. Discarding/recreating
the root was rejected because it would reset local consent/accounting. No screen
region is masked, animation frozen, failed admission resumed or input automatically
retried. Final controller/native image checks remain strict. If recurring visual
churn still prevents real Save, assess command-relevant equivalence across the
whole boundary; this observation correction does not guarantee liveness.
[#195](https://github.com/CVX-Hull/enactive/issues/195) owns live follow-through.

passive completion verification is evaluated before refusing another input.

recovery system, player ingress, wire shape, menu handler or renewed allowance.
The protocol and mixed-input design own the exact behavior and source/native
qualification limits. Pre-admission refusals remain ingress rejections; they are
not invented accepted operations or primitive charges.

## Memory and asynchronous reflection

The [procedure-learning design](../design/procedure-learning.md) owns the smallest
durable source-linked procedure representation, applicability and revision.
The player authors and tests abstractions; retained Claims/Work describe this
campaign, while procedures remain scoped, revisable candidates. Reuse in a distinct
situation, contrary-evidence revision and actual fresh-context retrieval/application
are distinct from storage or an accepted key. Learning006 supports branch
refinement; it does not establish falsification of an unsafe rule or causal gain.

The [reflection design](../design/asynchronous-reflection.md) separates useful play
from bounded advisory computation. Software schedules/claims jobs, persists
results and links offers, explicit procedure selections, inputs and outcomes.
The player/adviser judge applicability, conflict, uncertainty and meaning. Exposure,
selection, delivery and success remain separate; a source being exported does not
prove mental attention. Advice is data, never authority or a required per-key
approval. The lead must not become the tactical model or memory curator.

Use an assigned general-purpose advisory agent and the existing structured
claim/source/submit/result/advice path. Assignment is orchestration; subsequent
work scheduling and automatic bookkeeping belong to software. No separate paid
provider is assumed. Retain an actual host-concurrency failure if this integration
cannot progress rather than claiming nonblocking behavior from component tests.

## Reuse and tradeoffs

Keep CDDA's ordinary UI/activities, the native bridge, controller, single
MissionRuntime, JSON Schema validation, SQLite ledger/evidence archive, official
MCP SDK and Git/GitHub. No new executor, source-history store, vector database,
graph service or general agent framework is selected. Existing visible-row target
shortcuts precede coordinate clicks where applicable.

The October21 source probe found the pinned ImGui/SDL2 backend reads/warps the
physical pointer. Dear ImGui Test Engine's [implementation](https://github.com/ocornut/imgui_test_engine/blob/main/imgui_test_engine/imgui_te_context.cpp)
and [separate license](https://github.com/ocornut/imgui_test_engine/blob/main/imgui_test_engine/LICENSE.txt)
were considered. It would still need visible-only attestation and per-input custody,
and does not cover the game's mixed UI; it was not adopted for this slice. Revisit
a demonstrated gap instead of building a generic locator language or assuming
unverified version compatibility. Actual click/geometry remains a separate native
qualification from a schema or source fixture.

Trust configured DB/OS/library guarantees and implement residual domain rules.
Authentication no longer repeats archive sweeps after every ACK; actual consumers,
reopen and audit still detect lost evidence. This simplification is not a measured
latency claim. Assess whole-skill/tool/display cost with existing journals, SDK
records and maintained profilers before adding telemetry infrastructure.

P-CHANGE/S-CODE permit upfront accelerators over the project's longer horizon:
repeated use, learning, future cost reduction and new options can justify an
investment without immediate payback or a precise ROI. Consequential choices state
expected uses, uncertainty, upkeep and a reassessment trigger. Historical setup
cost informed [#175](https://github.com/CVX-Hull/enactive/issues/175)'s conditional
cross-admission checkpoint reuse. Ordinary reload currently proves a save within
its own mission; it does not import authority or resume a failed run. This is an
owned investment decision, not a blanket campaign prerequisite.
