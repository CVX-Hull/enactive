## Reuse and tradeoffs

The first implementation checkpoint coordinates native5/mission9/ledger11/
archive4/memory4, ordinary input, immutable procedure revisions, pinned historical
library, complete procedure handoff and the observer. Reflection record validation,
bounded passive mailbox and SQLite bookkeeping are source components; scheduling,
official adapter integration, actual advisory actor concurrency and lifecycle
quiescence are still pending. The native build passed, but no new graphical run
or seven-day acceptance is implied. Focused tests and source review remain
separate from actual game evidence and final protected CI.

Keep CDDA's ordinary UI/activities, existing native bridge, controller, single
MissionRuntime, strict JSON Schema validation, SQLite ledger/evidence archive,
official MCP SDK and Git/GitHub. No new input executor, log/history store, vector
database, graph service, generic agent framework or paid model API is selected.
The current visible-row MenuSkill already supplies useful target shortcuts.

The October21 source probe verified the owned pinned source has ImGui1.91.5 and
its SDL2 backend polls/captures/warps the physical pointer. The native worker must
inspect that source through the recorded build manifest, not assume ignored
upstream files are absent. Dear ImGui Test Engine's [current implementation](https://github.com/ocornut/imgui_test_engine/blob/main/imgui_test_engine/imgui_te_context.cpp)
includes compound automation/internal UI operations; its [own license](https://github.com/ocornut/imgui_test_engine/blob/main/imgui_test_engine/LICENSE.txt)
is distinct from the core library. No dependency is adopted for this first slice:
it would still require visible-only attestation and our per-input custody, while
not covering the game's mixed UI. Retain the existing label shortcuts and extend
the bridge's ordinary event handling. Revisit a library for a demonstrated gap;
do not build a general locator language or assume unverified version compatibility.

Reflection uses an assigned general-purpose Codex advisory agent and bounded
structured work/result tools. Assignment at admission is orchestration; subsequent
work selection, wake/wait/result persistence and exposure belong to software.
No configured API provider is assumed. If actual host concurrency cannot support
this path, retain that specific finding and repair the integration before claiming
nonblocking reflection. The lead is not a fallback reflective service.

## Ownership and checkpoints

The lead owns schemas, controller/runtime/ledger integration, player tools,
documentation, project settings, shared build/native runtime, admissions and final
verification. After interface freeze, at most two workers in separate worktrees:
one owns native bridge/header, upstream pin, count-checked patcher and focused
native-source tests; the other owns the pure procedure validation/projection module
and its focused tests. Exact paths, base, APIs and checks go in each bounded brief.
Do not split coupled writer/migration work between agents. One integrator.

Use development-first fast/focused checks and frozen finite attempts, reaching a
coherent behavior before consolidated full review/CI. Applicable native authority,
Pause, delivery, version, identity and cleanup failures still block affected input.
No routine action or procedure requires a human/automatic reviewer round trip.
Actual loaded MCP catalogue/preapproval is a setup check, not a per-action gate.

Before each run freeze source/native/configuration, sole player and advisory role,
update policy, initial library sources, objective, attempt identity, all finite
resource ceilings and protected ending. Forecast inputs, mappings, requests,
frames, bytes, wall and game time together. Reflection has separate finite
jobs/context/output/time limits within the same attempt; failure never refunds
spent cost or grants a new allowance. Missing model metrics stay unknown.

Measure representative end-to-end decision/tool/skill/display intervals during
use. Native ACK timing and fewer tool calls alone do not establish player speed.
Fix terminal viewer wording/reconnect in the same delivery. Evaluate #175 using
actual repeated setup cost; implement normal checkpoint reuse only if it materially
helps this work, with new admission provenance and no rollback/old authority.
