# A dedicated player with explicit takeover

For [#97](https://github.com/CVX-Hull/enactive/issues/97), keep gameplay observations
in a dedicated sub-agent context while the lead handles engineering and deliberate
inspection. The [first-day result](../acceptance/2026-10-18-first-day-completion.md)

waypoint planner remains candidate-only; a separately assigned general-purpose
campaign operator uses ordinary input only when no waypoint lease is live.
They are responsibilities in the same current contract, not compatibility paths.

The lead owns design, source/release, game/controller launch, admission, escalation,
integration and final verification. One clean-context named general-purpose player
owns ordinary input and its capture files during two explicit phases. Explorers
and reviewers remain read-only. The lead writes source alone; no source/native
changes or concurrent executor during the admitted probe. A worktree is unnecessary
for a player that cannot write source or launch processes. Independent source,
ledger, frame and outcome review is read-only.

Actor assignment and quiescence are workflow controls, not an exclusive external
capability. Shared tools/permissions are not isolated. The existing controller
serializes and checks input but cannot authenticate a sub-agent name. Do not claim
that a phase file prevents a malicious actor from impersonating another. Preserve
the distinction between deterministic authority checks and fallible visual judgment.

## Two player phases and deliberate inspection

1. Lead loads through ordinary UI, verifies actual world/name/calendar/needs and
   inventory applicability, invalidates old relative coordinates, then Pauses.
   A mismatched identity/calendar stops; summaries never supply current authority.
2. A prepared clean-context player receives the bounded checkpoint, fresh paused
   observation and explicit phaseA assignment. It reobserves, explicitly Resumes,
   inspects current needs and performs a useful ordinary decision: address actual
   thirst with visible usable clean water if available. It must verify actual
   consumption/outcome and distinguish carried from reachable supplies. No forced
   consumption if needs/supplies differ; report the actual gap and stop instead.
3. The player finishes all tools, Pauses and returns a source-linked checkpoint
   with consumed budgets, unknowns, last-seen facts and no further call scheduled.
   Lead verifies terminal agent/tool handles and empty live request/recovery/lease,
   Pauses and freshly observes for deliberate inspection. Missing/unquiesced tools
   are not treated as stopped; re-poll the same live handle. Native activity may
   continue after Pause and is never assumed canceled.
4. Lead records phaseB with unchanged aggregate budgets. The same player receives
   a new bounded assignment, fresh observation and explicit Resume. It inspects
   remaining usable supplies/needs and makes a bounded next-day resupply or
   conservation decision from actual UI; unnecessary eating/waiting is not required.
   Return a paused, quiescent checkpoint. Lead performs normal save/Quit cleanup
   with ordinary deadlines, retaining unknowns and separately checking process exit.

Only the assigned player sends ordinary inputs during its phase; lead status,
watching and emergency Pause remain available. Lead Observe/native inspection or
recovery waits for handoff. If a readable unsupported prompt is encountered, stop
the player and hand off; lead may use the already verified ordinary native-CUA
