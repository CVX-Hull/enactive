## 2. Ten-dimension assessment synthesis

### 2.1 LLM vs. code responsibility split
- **Code should own:** bounding actor-start briefings and recall indexes, tracking active leads already in context and passing an `already_in_context` ID list to recall, exact-ID-first selection, deterministic English stemming, coordinated spend/finish-reserve admission, halting uncertain batches, and opt-in post-batch visual settle polling.
- **Models should keep:** pixel interpretation, tactical decisions, Save/Quit choices, semantic recall selection over screenshots (pure lexical `bm25_1hop` cannot read pixels without empirical proof that `intent` strings carry all visual cues), and final reports.

### 2.2 Tool ergonomics and prompt hygiene
- **Stemmer defect (`harness/player/knowledge.py:411-419`):** Single-pass `_fold` folds `zombies` → `zomby` (`zombie` → `zombie`), `speed` → `spe` (`speeds` → `speed`), `focus` → `focu` (`focused` → `focus`), `spring` → `spr` (`springs` → `spring`), and `bleed` → `ble` (`bleeding` → `bleed`). Naive fixed-point repetition still fails `zombie`/`zombies` and collapses `speed`/`bleed` into truncated roots; English Porter2 (`snowballstemmer`, BSD-3) is the clean primary benchmark candidate.
- **Query payload weight:** Across the `20` `#924` `v91` queries replayed in `#936` on `bm25_1hop` (using the `Knowledge._result` envelope, `delivered-knowledge/2` → `player-knowledge/3` schema-valid hit projection, and `harness/jsonio.py:31` `canonical` UTF-8 serialization described above), full deep-copied `/2` records have `10,946 B` median (`15,193 B` max, a conservative lower bound for `/3`), whereas discriminated compact hits (`id`, `kind`, `title`/`subject`, `claim_kind`/`scope`, `240`-char snippet, `tags`/`cited_by_articles`, `via: "match"|"hop"`, non-empty `status`) reduce total bytes across the 20 queries by `64.0%` (`232,144 B` → `83,508 B`) and median bytes by `62.0%` (`4,155 B` median, `4,457 B` max).
- **Prompt redundancy and typos:** `docs/player-guide.md` and `harness/player_tools.py` repeat "delivered is not success" three times, status flags three times, and resolution tables twice, while omitting guidance on when to query or cite; `player_tools.py:19`, `application.py:61`, and `runtime.py:31` / `player_view.py:46` contain spacing typos (`Send1..32`, `Text≤31UTF8`, `within8192`, `be32`).
- **Dead code (`#946`):** `tools/player_host/validation-feedback.mjs` (`81` lines, `0` triggers) targets retired `intent.anyOf`; `harness/player_view.py:35,40-42,44` retains `7` globally unproduced legacy error strings (`'Unknown memory-query fields'`, `'Yield/done actions must be null'`, `'Selection requires exactly crop and size'`, `'Selection size requires two dimensions'`, `'Crop requires x,y,width,height'`, `'Crop exceeds the captured image'`, `'Program duration must be finite within (0,20] seconds'`).

### 2.3 Context, working memory, caching and cut hysteresis
- **Formal cut/eviction model:** Let `T` be active context tokens minus `currentBriefingTokens`, `I` raw active images, `P` protected latest-batch images, `M` `max_context_images`, `B` `context_image_block`, and `O_-` prior omitted images. For `P <= M`:
  $$O(I, P) = \min\!\left(I - P,\; B \left\lceil \frac{\max(0, I - M)}{B} \right\rceil\right)$$
  On `main`, `high_mark` (`T > H`) remains level-triggered, `cutContext` (`host.mjs:1314-1339`) can break before `min_free` even when more covered turns exist, and hard capacity (`contextWindow`) stops at equality (`>= contextWindow`) even when `T <= H` if `H` approaches `contextWindow - maxTokens`.
- **Working-memory continuity across cuts:** Including the last `5` distinct validated public `intent` strings from removed turns (accumulated across cuts, keeping the most recent occurrence at the tail) inside `BEGIN CONTEXT CUT` carries zero extra model calls and zero violation of [ADR 009 (curated player)](decisions/009-curated-player.md) (no player-authored durable memory). Because sampled `#896-b` intents were short tactical strings (`64`-char median, `105`-char max from a one-off sample), continuity benefit remains a hypothesis to verify in live play.
- **Halving-step tail notices:** Currently `host.mjs:1474-1480` appends a new user message on *every* turn once a threshold trips. Re-emitting only when remaining capacity crosses fixed halving steps (`100%`, `50%`, `25%`, `12.5%`, combining simultaneous kinds) keeps notices bounded (`<= 4` steps per kind per epoch) while preserving countdown feedback for a clockless model.

### 2.4 Lifecycle, state-machine soundness and adversarial resilience
- **14 grouped contract-preserving bugs (`#946`):** Verified across `tools/player_host/host.mjs`, `tools/player_host/knowledge.mjs`, `harness/player_client.py`, `harness/player_mcp.py`, `harness/player_view.py`, and `tools/campaign_player.py` — covering fail-closed `streamFn` reason masking, pre-cut update-list refusal when a same-turn cut makes room (narrow `player-host/11` fix, distinct from `#947`'s full atomic joint update+cut planning), in-flight recall stale-version injection, uncertain `computer_input` batch continuation, `pendingHandoff` bypass and refusal stranding, `player_client.py` pending-handoff sealing, malformed JSON `AttributeError`, failed-collection wrong UUID/collector, blocking HTTP in `player_mcp.py` signal/cancellation handlers, `PlayerError` SQLite diagnostic leak, driver grace-exhaustion reason masking, post-terminal deadline race, chunk-dependent SSE peeking, reused `toolCallId` provenance overwrite, JSONL framing edge cases, `selection()` ID-vs-title precedence, and dead-code/typo cleanup.
- **Spend vs. `finish_reserve` race:** Ordinary player fetches ignore `finishReserve` and `unpricedBound`, racing the driver's `100 ms` `host.jsonl` poll. Closing this cleanly requires a terminating `spend-reserve-reached` handshake and releasing `finish_reserve` only on a request whose projected context contains the accepted `control_id`.

### 2.5 Mathematical and control-theoretic foundations
- **Adopted / applicable:** Discrete hysteresis & prefix-cache amortization (`arm-on-pressure`, smallest sufficient `k in [min_free, E]` on actual post-cut projection, independent strict-fit hard-capacity rescue, at most one prefix rewrite per transform); active sensing / monotonic quiet-time polling for opt-in post-batch visual settle; future hierarchical options (programs and monitor phase [#177](https://github.com/CVX-Hull/enactive/issues/177)).
- **Rejected under [the control rule](standards/authority.md#control-review) (`R-CONTROL-BLOAT`):** Pixel-space POMDP solvers, neural world models, bundled tokenizers ([owner decision](decisions/owner-decisions.md#provider-usage-counts-player-context)), turn-count kill switches duplicating `C-RUN-LIMITS`, and speculative guards without observed failure modes (turn-image cap, update-lead clip).

### 2.6 `S-CODE` library reuse and dependency review
- **Shared `delivered-knowledge/3` validation parity (`#925` rule kept):** `#925` (`docs/design/knowledge-graph-scoping-contract.md`) reaffirmed that the Node player host adds **no** validation dependency (`typebox@1.3.27` is only a transitive dependency of the host runtime, not a direct `package.json` entry, and `ajv` is absent from the lockfile). Keep `tools/player_host/knowledge.mjs` dependency-free and harden shared fixture parity across Python and Node (explicit vectors for terminal `\n`, `U+FEFF`/`\x1c-\x1f`/`\x85`, integral JSON numbers, and one safe-integer version domain rejecting `v9007199254740992` in both languages).
- **Stemming (`snowballstemmer`):** Pure-Python BSD-3 English Porter2 implementation, pinned in `requirements.in` with hashes generated into `requirements-dev.lock` only if the retrieval-regression gate confirms clean improvement over `_fold` with zero Hit@5 / Article MRR@5 regression on `#936` queries; **reject `nltk`** (runtime corpus downloads violate `P-ISOLATION`).
- **Host runtime SDK & provider modularization:** The pinned `1.4.0` host runtime already bundles multi-provider APIs, yet `host.mjs` hard-locks one completions API and one routing provider at seven sites (`:8/:112`, `:131-162`, `:559-597/:855/:1765`, `:842-845`, `:1556`, `:1655-1656`, `:681/:691-694`). Factor these into a closed `PROVIDER_PROFILES` map; keep the pinned `1.4.0` runtime unless a dated upstream need justifies an upgrade with `$1` `C-MODEL-CHECK`.
- **Image processing:** Reuse already-pinned `Pillow==13.0.0` and `numpy==2.5.4` in Python for any decoded-pixel comparison or lossless crop; **reject `sharp`** in Node (native libvips conflicts with `--ignore-scripts` CI and layer ownership).
- **Explicitly rejected external agent frameworks:** General workflow-graph libraries, multi-agent chat orchestrators, and coding-agent harnesses as player hosts — all violate byte-stable prompt-cache prefixes (context-stability finding [#489](https://github.com/CVX-Hull/enactive/issues/489)), exact `context-manifest` hashing, `C-SPEND` ≤2-attempt bounds, no-replay custody (`C-RUNTIME`), and `player-host.md` isolation (`:550-555`).

### 2.7 Six-genre `P-GENERALITY` cross-game stress test
Zero CDDA symbols leak into the player runtime, yet six structural biases appear across genres (bounded by `docs/charter.md` CDDA-class scope, portability outcome [#191](https://github.com/CVX-Hull/enactive/issues/191), and [second-game deferral](decisions/owner-decisions.md#second-game-waits-for-owner-choice)):

| Genre | Mechanical control (`protocol.py`, `bridge.mm`) | Observation & ports | Host loop & memory | Ownership split |
| --- | --- | --- | --- | --- |
| ASCII roguelike (CDDA) | Single end-of-batch capture; `89.7%` terminal waits | Full PNG only; `v91` query median `10,946 B` | `51,601`-char start brief; `71.1%` pre-cut dup leads; `2,215` holds | Fix in player architecture RFC [#947](https://github.com/CVX-Hull/enactive/issues/947) |
| Real-time action / platformer | No `key_down`/`key_up` holds or simultaneous chords | Single PNG gives zero velocity; no audio | `4.95 s` p50 sequential LLM loop too slow | `#177` (programs/monitor) + `#191` |
| Mouse-driven RTS / 4X strategy | No `mouse_move`, `drag`, `wheel`, `double_click`, `middle_click`, `F1..F12` | Dense HUD/minimap lacks region crop | Same start-brief bloat & `computer_input`-only recall cadence | Briefing/recall in `#947`; inputs in `#191` |

| Point-and-click / dense GUI | Missing hover, wheel, drag, double-click; 31-byte text cap | Small UI text benefits from lossless crop | Long lore stores hit start-brief cap; observe-heavy turns skip recall | Briefing/optional crop in `#947`; inputs in `#191` |
