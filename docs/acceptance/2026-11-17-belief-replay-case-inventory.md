## Shared replay contract and dry check

Freeze case IDs, the ordered exposure list, the scope and question, and one common
human-authored extraction with origin, event reference, dependency group and
polarity or unknown. The update before an answer frame cannot access that frame
or its label. For a revision pass, give both updaters the same new extraction
and ask the same question again. The common readout returns the answer or
abstention and applicable source IDs under one rule. A future model reader
keeps the same prompt, inputs and limits across arms. Comparison of
presentations and model-mediated extraction are separate questions.

The qualitative arm uses the existing `revision_state` helper on supplied
origin alternatives. A duplicate reference does not create a second alternative.
Removal of the only supporting origin returns the case to unknown. Distinguish
support-only, refutation-only, conflict, and no applicable evidence. The
positive inventory assertion and its contrary stand-in are complementary
queries about one frame, not two independent observations.

For a mechanical example only, use `W=2`, `a=1/2`, and unit weight for one
manually supplied polarity, once per canonical origin. For the inventory query
the supplied prefix starts at `r=s=0`; the constructive update on capture 210
sets `r=1, s=0`. The contrary query uses `r=0, s=1` on the same origin.
`evidence_views` gives opinion/Beta mean `2/3` and `1/3` respectively, and
repeated exposure to 210 does not change them. The Quit-delivery question
receives no update. Its qualitative unknown stays unknown. The numerical
prior does not predict the disposition of an unobserved input. The existing
matched-opinion/Beta tests also exercise a supplied conflicting pair through
both views. These weights and examples test plumbing. They do not quantify
frame reliability, justify aggregating related messages or estimate a CDDA
probability.

## Sufficiency and next price inputs

The development inventory is sufficient to wire one replay path and test
revision, repeat-origin resistance and abstention. It cannot establish
calibration, compare predictive loss between independent methods, or justify
a paid experiment sized for a production decision. Before asking for a price,
identify permitted uninspected whole-world source groups that can produce both
positive and negative endpoint labels under the same rule. Include explicit
refusals, later re-observations or corrected/conflicting applicable evidence,
and useful later reader questions. Predeclare the horizon and unknown policy,
a blinded source-label check and a defensible prior and observation-to-weight
mapping from development evidence. Freeze source splits and numeric loss before
looking at held-out outcomes. Preserve all assigned targets in coverage and
keep qualitative abstentions separate from probabilities.

For a possible later bounded experiment, count `P` newly qualified prefixes
and `Q` assigned paired queries or fixed revision checkpoints. The first-stage
deterministic updaters cost zero model requests. If a later design uses model
extraction, count up to one shared extractor request per frozen evidence batch
and list the number of batches before pricing. A model readout on the matched
arms would take `2Q` requests per repeat. If endpoints use two independent
model labels and at most one disagreement adjudication, budget `2Q` plus up
to `Q` requests, without multiplying labels by the number of arms. List
acquisition, additional prefixes, any separately tested model updater
(two requests per assigned prefix-batch and repeat), and repeats or failures
explicitly. A failed attempt consumes its allocation. Capture token and time
ceilings and the frozen route for each role, and apply the [#668 worksheet](2026-11-16-cdda-recurrence-preparation.md#proposed-price-and-remaining-decisions).
The unsupported groups and coverage leave `P`, `Q`, batch counts and any
funded total open. Stop before paid replay if these inputs cannot support the
claim sought.
