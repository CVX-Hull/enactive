# P1's power gate passes on four held-out lineages (#178)

On 10 November 2026 #178 wrote the probes for held-out lineage `lh4`
([run record](2026-11-09-held-out-lineage-522.md)) and re-ran the power gate that

## The gate

`python -m tools.p1_analysis simulate --probes data/evaluation/p1/held-out/probes.jsonl --probes
data/evaluation/p1/held-out-lh4/probes.jsonl --out data/evaluation/p1/power-held-out-study-2.json`
wrote [`power-held-out-study-2.json`](../../data/evaluation/p1/power-held-out-study-2.json): the
unchanged rule on the four lineages' actual units and clusters, 5,000 simulations per effect size.

| True effect (B − A) | 0 | 0.10 | 0.15 | 0.20 | 0.25 | 0.30 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| P(go), lh1–lh4 as frozen | 0.022 | 0.195 | 0.355 | 0.574 | 0.764 | 0.901 |

The gate needs P(go) of at least 0.80 at the effect of interest (0.30) and at most 0.05 with no
effect. It has 0.901 and 0.022.

- **Frozen inputs.** The command refuses a probes file that differs from its directory's freeze,
  and the output records both: `held-out/probes.jsonl` `1e26849b…` under `frozen.json` `7bfaa78a…`,
  and `held-out-lh4/probes.jsonl` `26e50a93…` under `frozen.json` `bab54826…` (50 files).
- **Order.** `lh4`'s freeze was committed (`669057a`) before the gate ran.
- **Against the plan.** The plan drew `lh4`'s units per boundary from lh1–lh3's (2.7 on average)
  and gave P(go) 0.884 at 12 boundaries. `lh4` has 13 boundaries and 4.8 units per boundary, so it
  is about twice the planned size; its clustering, 1.32, sits between the plan's 1.04 and 1.4
  rows. The gate uses the actual structure, as p1-study/2 says it must.

## What the gate does and does not show

The study can now detect the effect it was built for: with a true gain of 0.30 it ends in a go
about nine times in ten, and with no gain about one time in fifty. It says nothing yet about
whether a curator helps. No arm has been replayed and no unit scored. The simulation covers the
primary criterion only; the guards and re-judging are not simulated.

## Deviations and procedure

- **Delivery.** Each judge, writer and annotator wrote its JSON Lines to a named file and replied
  only with a line count, so the lead never saw their content. The briefs were otherwise word for
  word, with their placeholders filled.
- **Annotators.** Each received the earlier chunks' annotation files in order as its incoming
  ledger; from the fifth chunk the brief named their directory once and listed the file names.
  The next fact ID came from a count of earlier `fact` lines. The first chunk had boundary "none"
  and an empty ledger. The labels file was the working copy the lh1–lh3 annotators used
  (`8b87f0c2…`).
- **Two corrections before the freeze, both to `lh4b5-002`'s ledger.** The freeze first refused it
  for a `carry` line on a fact that an earlier chunk had invalidated (F26), then for 40 live facts
  with no `carry` line (F42–F83, less F57 and F64). The same annotator, in its own context, removed the
  one line and added the forty. The lead then asked it to account for a line count that looked
  short; it answered that its event lines were unchanged at 23, and the lead's estimate of 40 had
  been a miscount. The lead read fact IDs and line types only.
- **One annotator's procedure.** `lh4b4-001`'s annotator wrote its file with a Python command
  instead of the Write tool, and its reply named fact IDs and counts but no fact content. Later
  briefs' delivery line said to use the Write tool and reply with the count only.
- **Query writers.** All thirteen met their frame-coverage requirement and ended with their end
  line; none needed a correction.
- **Hosts and models.** Development agents ran as general-purpose subagents of Claude Code on
  Sonnet 5.5, the model of the #490 judges, each in a fresh context.
- **Code.** The lineage map merged in #525 before any `lh4` file was read by the tooling.
