## Limitations, gaps and unknowns

- Codex loads project rules and `.codex/config.toml` only for a checkout trusted in
  the user's own configuration; a nested clone does not inherit trust and a
  `-c projects…trust_level` override did not enable project files. File-based Codex
  loading and the live rule check therefore ran at the already user-trusted main
  checkout, with the user's own stale ignored `.codex/config.toml` moved aside and
  restored byte-identically afterwards. No user configuration was edited.
- The Codex `not_match` live result is the model's reported command output, reproduced
  in two runs; this Codex version emitted no command execution event for it. The
  allowed-command result has its execution event.
- Claude Code applies project `.claude/settings.json` only after the workspace trust
  dialog; the check passed it with `--settings`. With the user's `auto` permission
  mode, a `not_match` command was approved by the mode, not the project; the check
  pinned `--permission-mode default`.
- One adapter is listed. Replacing it with a second adapter is designed for but not
  demonstrated.
- The investigation and analysis tools now reject pre-migration `pi-player-host/4`
  traces and `campaign-run/2` packages as inert history (S-MIGRATION); earlier
  campaign evidence remains readable as files but not through current analysis.
- The adapter's real-MCP discovery case failed once under heavy local load during
  development (5 s MCP startup) and passed in every later run, including the full
  profile. Not investigated further.
- Diagram re-rendering on this machine changed embedded font subsets in unrelated
  SVGs; only the three edited diagrams were committed.
- The user's local `.codex/config.toml` at the main checkout predates this change
  (it names removed tools and lacks `--actor-config`); regenerate it from the
  coding-agent hosts page when an actor is issued.
