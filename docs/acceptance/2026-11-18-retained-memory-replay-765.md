## Paired packet dry run

Each paired row joins to one byte-identical common file. Both arms reserve
2,048 input tokens for the optional pre-cutoff readout and cap output at
512 tokens separately. The readouts are source-linked packing fixtures.
They use an earlier assigned observation, before the cutoff or outcome.
Actual retrieval and selection by a memory system require their own test.
Both arms can propose the same lookups and fresh checks, with no dispatch.

The full rows keep the recorded message parts and their image projection.
For the compact rows the serializer drops the oldest complete request turns
until common input plus the reserve fits 65,536 tokens. The system, original
prompt, delivered knowledge and current view stay in every row. Selected
turns keep call/result pairs and recorded omission references. The same
source permissions and projected image treatment apply to both arms.
The dry serializer uses the same Pi estimate module as the [player host](../../tools/player_host/host.mjs). The retained packing result gives its SHA-256.
For framing it counts its serialized role and call structure, objective,
and the current public tool declarations. Untrimmed rows also respect the
recorded host estimate for sizing. This is a reproducible offline estimate
for the fixture. Actual provider tokenization and tool serialization still
need verification before a paid comparison.

## Next evidence

Prepare a targeted new development capture before pricing another replay.
Choose a capabilities or equipment start only if normal play makes an
earlier equipment-location or method fact plausible, with a later choice
that verifies or uses it. The Whitethorn example supplies the shape.
Observe a specific usable tool or substitute at a source-linked spot,
record its condition and any ownership, and capture the clock and the
named survivor. After ordinary intervening work, capture a decision
between returning to check that spot and another feasible method. Natural
rest and reload may create the later opportunity. Keep the normal report
intact. Capture the current view, actual ordinary sent parts, delivery
and available source IDs before the choice. Then keep the next operation
and a visible result such as finding and using the item, plus a named
living view near that effect. Record whether local inspection, a cheap
source lookup or a fresh search could have answered the question and
at what effort. Stop at a missing case or ordinary-context control
when that is what the finite assignment yields.

Whitethorn can support a bounded proposal-only replay if that question
is selected later. Use its one reconstructed current-history request 19
row, two repeats per condition, four responses total and 512 output
tokens each. Score grounded local verification, reasonable recipe
preparation and uncertainty blind. The compact row retained identical
history, so it supplies no separate size contrast. The existing #755
proposal evidence and missing retrieval effect make targeted capture
the recommended next step. Independent worlds and a separately frozen
visible outcome remain necessary for a matched gameplay comparison.
Evidence work minimizes [R-FALSE-CLAIM](../risks.md) by preserving the
