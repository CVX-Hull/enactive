## What P1 inherits

1. **Probe recall depends on adjudication.** Blinded fact-level annotation tied each
   known need to a neighbouring fact. #178 should test held-out annotation against
   episodes found another way before relying on blinded recall. It should also fix one
   fact ledger and score every arm against it.
2. **The cost figure needs prompt caching fixed.** Neither the curator host nor the
   actor's host sets a session ID, so no session-affinity header reaches OpenRouter. The
   curator proxy would drop one anyway. The likely fix is one affinity value per
   session, set by the proxy for the curator and by the host for the actor. That is a
   hypothesis until one paid session tests it.
3. **Starting point for curator spend.** Terra cost about 0.6× the actor's spend on the
   long lineage, and Opus about 1.2×. The #454 record suggests capping a P1 offline
   replay at 1× actor spend per game hour, with terra and the controlled host. ADR 009
   open decision 2 stays open for P1.
4. **Measured carry rates.** Within an admission, actor handoffs kept about three
   fifths of what the predecessor held. Admission boundaries kept about a third.
   Rediscovery ran at about four per game hour on #397. These are the baselines P1's
   arms are compared against offline.
5. **Snapshot diffs and cache rewrites.** The #455 estimate found that one 200-token
   snapshot diff adds about 5–14% of an average request's cost. It also found that the
   actor's large cache rewrites, 8% of #397's requests, carried 58–66% of each
   admission's spend.
   - Most of those rewrites follow a prompt shorter than the request before.
   - The actor's host has no pruning or compaction, so its only prompt-shortening
     mechanism is image-block eviction. The attribution is not confirmed.

   Like item 2, this points to prompt-cache stability as P1's main cost lever.
6. **A review of every model's context comes first.** On 8 November the owner asked
   for a review of everything sent to the actor and the curator, for cache stability
   and for clarity in every scenario. A read-only inventory found three stability
   problems:
   - a per-actor ID inside the actor's system prompt;
   - a tool table that changes at the last handoff;
   - image-eviction markers that omit the frame's source ID.

   It found two clarity problems:
   - context-capacity and provider-error stops that tell the model nothing;
   - a one-time context warning that vanishes from later requests.

   These are inputs to the discussion that precedes the P1 decision.
